ledger

    rules

    Six rules. No exceptions.

    At mainnet the server enforces them. In beta, the tab you are mining in checks every proof the same way.

    1. R1

      One challenge per round

      Every 60 seconds a new challenge is derived from the round number. Anyone can recompute it, so nobody can mine ahead.

    2. R2

      A proof is a nonce

      sha256(challenge · address · nonce) must start with at least 22 zero bits. That takes about 4.2M tries on average.

    3. R3

      One hash to check it

      Every submitted proof is hashed once more. If it doesn't hold, it earns nothing and shows as rejected in the ledger.

    4. R4

      Deeper counts double

      Each extra zero bit halves the odds, so a proof with d zero bits is credited 2d−22 units: the work it statistically took.

    5. R5

      Deepest takes the bonus

      The single deepest hash of each round takes 20% of that round's pool. The rest splits by credits.

    6. R6

      Paid from real fees

      80% of $ZEROS creator fees fund the pool and 20% keeps the servers on. During beta, credits are tracked and nothing is paid.
